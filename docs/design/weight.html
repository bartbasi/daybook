Daybook design / Weight entry and widget

Weight entry and widget

Reliability is the requirement: every save is written to the database at once and confirmed on screen from what was read back. Speed: Weight is one of the three buttons on Home and the only widget.

Frame width: 360 dp (phone) 344 dp (Z Fold 5 cover screen) 673 dp (Z Fold 5 unfolded)
Speed target: log body weight. Target: under 5 seconds from Home, or from the widget.
  1. Tap Weight on Home (or the widget).
  2. The sheet opens with yesterday's 182.4 already in the box and selected, with the number pad up.
  3. Type the new weight: 5 keys for "181.8". (Skip this if it is the same.)
  4. Tap Save next to the box. (Android's number pad also has a Save key; the iPhone decimal pad has no action key, so on iPhone it is always the Save button. The count is the same.)
From Home: 2 taps plus 5 keys, about 3 to 3.5 seconds. 2 taps if unchanged, about 1.5 seconds. Pass (estimate).
From the widget: the same, plus the app opening, about 3.5 to 5 seconds. Pass if the app opens to the sheet in under 1.5 seconds from cold. That has to be measured on the phone in Phase 4. Estimates assume about 0.35 s per key and 0.5 s per tap.
Decision for Bart: the widget opens a quick-entry view. Home-screen widgets on Android and iOS cannot hold a text box. Chosen: the whole widget is one tap target that opens Daybook straight to the weight sheet, prefilled. Why: one way of saving weight (the same code, the same tests) for the feature where reliability is the requirement; any value can be typed; it works on every iOS version that has widgets. Rejected: - and + steppers with a Save button on the widget. A change of 0.6 lb is 4 taps and 2 lb is 11; it needs iOS 17 or later; the widget would have to write to the database from a separate process (a second write path to test); and a widget that saves is easy to set off from a pocket.
Decision for Bart: the trend line. Chosen: each day the trend moves 10% of the way from yesterday's trend toward that day's weight (an exponentially smoothed average). Days with no weigh-in keep the trend flat. Days with more than one weigh-in use their average. Rejected: a plain 7-day average (jumps when a high day drops out of the window), and using only the first weigh-in of a day (simpler, but a second weigh-in would then seem to be ignored).

Delete in the edit sheet removes the row from the list at once and offers Undo. No "are you sure" popup. The entry is marked deleted rather than erased, so a health sync can never bring it back.

The trend is recalculated without it: 183.0 becomes 183.1 lb, and the Nov 11 dot is gone.

Home-screen widget

Shows the last weight, its date and the trend. The whole widget is one tap target. It opens Daybook straight to the weight sheet (frame 1), with the last weight selected and the number pad up.

Resizable; the smallest size (2 by 1 cells) shows only the weight and "Tap to log".

The widget reads a small copy of the last weight that the app writes on every save. It never writes.
