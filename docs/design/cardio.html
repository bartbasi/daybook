Daybook design / Cardio entry

Cardio entry

Sample: a 30-minute run at noon on Thu, Nov 12, after breakfast.

Frame width: 360 dp (phone) 344 dp (Z Fold 5 cover screen) 673 dp (Z Fold 5 unfolded)
Speed target: log a cardio session. Target: 1 screen.
  1. Tap Cardio on Home (or Log cardio on the Workouts tab). The last activity, Running, is already picked, and Duration has the cursor with the number pad up.
  2. Type 30, tap Next on the number pad, type 3.1.
  3. Tap Save.
1 screen. Pass. Taps: 3 (open, Next, Save) plus the numbers. On iPhone the decimal pad has no Next key, so the second tap is on the Distance field instead: still 3 taps. A different activity adds 1 tap (its chip) or a search (Other...). The very first time there is no recent activity, so Other... and a search are needed. Heart rate and the calorie override are optional.
Decision for Bart: gross MET. Chosen: calories = MET x body weight in kg x hours, as the brief words it. The sample run is 9.3 x 82.46 x 0.5 = 383 kcal. Rejected: (MET minus 1) x kg x hours, which avoids counting resting energy twice, because the calorie goal already includes it. For the sample run that is 342 kcal, about 41 kcal less, all of it added back at 100%. See docs/phase-3-summary.md, decision 6.
Decision for Bart: preselect the last activity. Chosen: the most recent activity is picked when the screen opens, so a repeat run needs no activity tap. Alternative: nothing picked, which costs 1 more tap every time but can never log the wrong activity silently. The picked activity is always shown in bold above the fields.

One screen: activity, duration, optional distance and heart rate, calories, Save.

Activity chips are the user's recent activities (up to 3), then Other.... The row wraps, so all of them are visible without a swipe. Duration has focus.

First use: no recent activities yet, so only Other... is shown and nothing is picked.

Date and time default to now; Change picks another day or time.

The estimate updates as the user types: MET x body weight x time (gross MET). 9.3 x 82.46 kg x 0.5 h = 383 kcal (181.8 lb is the latest weigh-in).

With a distance, the pace picks the Compendium entry. Running speeds are listed as bands (5.0 to 5.2, 5.5 to 5.8, 6 to 6.3, 6.7, 7 mph, and so on). The entry whose band holds the pace is used: 3.1 mi in 30 min is 6.2 mph, inside 6 to 6.3. A pace in a gap between bands uses the entry with the nearest band edge, and on a tie the slower one. Values are never blended.

Without a distance, the activity's entry from last time is used (or its general entry the first time). Change lists the other entries for that activity.

Heart rate is saved with the session but not used in the estimate.

Code 12050 at 9.3 MET is the 2024 Compendium value.

Typing a number in Calories overrides the estimate; both are saved (estimate and override), so the estimate can be restored with Use estimate.

The bar always says which number will be used: "your number" or "estimate".

On iPhone the decimal pad has no Save key; the Save button in the bar is used, as on Android.
